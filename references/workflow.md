# macOS 操作流程

## 环境检查

检查 `python3 --version`、`xcrun --find lldb`、微信应用 Info.plist 与 `codesign -dv --verbose=4`。在微信容器中查找 `db_storage`，明确目标账号目录。数据库路径会随版本变化，显式指定路径。

先在微信中确认目标消息范围。缺失的历史记录需要通过微信支持的迁移方式补齐。本地导出范围取决于设备实际保存的数据。

技能导出脚本需要 Python 3.10+、`sqlcipher3`、`zstandard`。仅在本地虚拟环境中补齐缺少的库。优先使用兼容当前 Python 与处理器的预编译包，避免引入编译环境。验证脚本仅使用 Python 标准库。

## 获取数据库密钥

上游项目：[TANGandXUE/wcdb-key-tool](https://github.com/TANGandXUE/wcdb-key-tool)。研究时核对的提交为 `79f1b5b92e12c66aa281b4a60a3c478b5f547dfa`。后续版本需重新审阅 macOS 脚本，尤其是临时文件、秘密保存、日志和进程清理逻辑。上游代码未包含在本技能包中。

上游 macOS 实现使用 CommonCrypto 和 LLDB。较新版本在系统密钥派生函数处捕获密钥材料，再逐库派生并通过 HMAC 验证。需要管理员权限及可调试的微信进程；具体兼容性以当前设备验证结果为准。

应用副本操作：将应用复制到本地工作目录，记录原应用状态，调整副本签名后启动副本。用户需要参与系统验证和账号登录。调试器附加准备完成后再进行账号重新登录，避免错过捕获时机。

管理员进程可能受到 macOS 文件访问权限限制。此时让用户从具有所需文件访问权限的终端运行已经检查过的本地命令。密码直接输入系统界面或终端，不发送到聊天中。保持 SIP 当前设置，不为此流程自动修改系统保护设置。

密钥文件结构使用上游 `all_keys.json` 格式：顶层为数据库相对路径；各项包含 `enc_key` 和 `salt`。这些值只在运行时从用户本地文件读取。上游 `extract` 命令通过 `--db-dir` 指定数据库目录，通过 `--output` 指定密钥文件，通过 `--timeout` 设置等待秒数。

## 保存一致副本

用户正常退出微信后，确认主进程结束，再完整复制 `db_storage`。保留 WAL 和 SHM 文件。即使微信已经退出，WAL 仍可能包含已提交数据。

上游逐页解密脚本不读取 WAL。本技能通过 SQLCipher 直接打开加密副本，由数据库库处理 WAL，并执行 `integrity_check`。

## 导出和核验

在技能目录执行以下命令，尖括号参数由当前任务的本地值替换：

```bash
python scripts/export_chat.py \
  --database '<数据库副本目录>' \
  --keys '<本地密钥文件>' \
  --contact '<精确联系人名称或账号>' \
  --owner '<当前账号标识>' \
  --account '<本地微信账号目录>' \
  --output '<本地导出目录>'

python scripts/verify_export.py '<本地导出目录>'
```

可用 `--start YYYY-MM-DD` 和 `--end YYYY-MM-DD` 限定消息范围，按 Asia/Shanghai 自然日包含首尾日期。全会话导出保存该会话独立目录中的本地附件。限定日期时，仅复制在选定消息 XML 中出现的媒体摘要匹配文件和选定消息语音。不能确定日期归属的附件不进入日期限定结果。能够通过摘要关联的附件显示在对应消息下面，其余全会话附件保存在目录和清单中。

输出包含 `chat.html`、`chat.txt`、`chat.json`、`attachments.json`。HTML 具有正文搜索、发送者与日期筛选及分页。JSON 保留原始消息字段。未知媒体类型和未解密媒体保留明确状态。

核验失败应就地终止并检查真实数据。对导出记录数量、完整性、身份与附件路径完成验证后再交付。没有执行浏览器交互测试时，不声称页面交互已经实测。
